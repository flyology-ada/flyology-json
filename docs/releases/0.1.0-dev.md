# `flyology_json` 0.1.0-dev release record

## Identity

This development release is identified by the exact source commit in the
Flyology Alire index manifest at
`index/fl/flyology_json/flyology_json-0.1.0-dev.toml`. It intentionally has no
Git tag. The manifest copies the source `alire.toml` and adds only an origin
table that pins that commit and
`git+https://github.com/flyology-ada/flyology-json.git`.

The crate has one dependency identity: `gnat >=13 & <17`. It has no Git pin,
path pin, runtime dependency, or committed compiler-provider lock. Original
source, tests, documentation, corpus tooling, fuzzing, and benchmarks are
available under `MIT OR Apache-2.0`.

## Public release surface

The installed public units are:

- `Flyology_JSON`, `Flyology_JSON.Errors`, and `Flyology_JSON.Profiles`;
- `Flyology_JSON.Parsing` with caller-driven `Step` and batched `Drain`;
- `Flyology_JSON.Writing` with whole-document destination transactions;
- `Flyology_JSON.Tokens` for bounded caller-storage collection;
- `Flyology_JSON.Numbers` plus checked signed and unsigned integer children;
  and
- `Flyology_JSON.Destinations`, the writer destination status vocabulary.

`Ordinary_Compact` is deterministic for one caller call sequence and preserves
exact validated number lexemes and member order. It is not canonical JSON.

## Reproduction and compatibility evidence

The maintained CI matrix builds and runs the complete `alire.toml` test action
on macOS 15 and Ubuntu 24.04 with GNAT 13.2.2, 14.2.1, 15.3.1, and 16.1.0.
It also builds benchmark adapters in portable and native modes on both
operating systems with GNAT 16.1.0, Rust 1.97.1, Node 24.19.0, and npm 11.17.0.

`Release reproduction` accepts this exact origin commit. Its candidate mode
tests a `git archive`, constructs the proposed development manifest, and runs
`alr index --check`. After publication, its indexed mode uses an isolated Alire
configuration, adds the Flyology index ahead of community, resolves
`flyology_json=0.1.0-dev`, verifies the deployed Git commit, and reruns the
crate's test action. Neither mode uses a downstream Git or path pin.

The APM evidence uses CLI 0.28.0 and runs `apm install --frozen`,
`apm compile --target codex`, and `apm audit --ci`. Generated `AGENTS.md` files
come from the committed local instruction packages and locked shared packages;
they are not source authority.

truncated input, exact offsets, UTF-8 and Unicode escapes, surrogate pairs,
number grammar, decoded-name duplicates, arbitrary Ada bounds, exact storage
and depth limits, reset/abort/reuse, task interruption, destination failure,

The complete provenance, license digests, selections, exclusion ledger, and
profile-specific expectations are recorded in
`docs/reviews/corpora/2026-08-24-provisional-corpora.md` and the corresponding
lowercase directories under `tests/corpus/`.

All 394 executable fixtures run monolithically, in one-byte chunks, and under
deterministic randomized schedules. Malformed schedules must preserve the
monolithic error code and byte offset. Bounded transition fixtures additionally
exercise every split and every retained partition in focused tests. The direct
full-corpus every-split planner computes 82,539,090,222 work units because two
large adversarial truncation fixtures make it quadratic; by explicit user
direction it refuses before parsing instead of launching that very large loop.

The writer corpus contains four project-owned event tapes. Every token runs as
one fragment, one octet at a time, at every split, and under four deterministic
random schedules. Golden output is checked byte-for-byte, reparsed through the
public parser, and accepted by Node's independent JSON parser.

Corpus labels and differential agreement are evidence rather than authority.
Historic JSON.org JSON_checker files are not vendored because their license is
incompatible with this repository's source policy.

## Performance evidence

The current-commit weekly workflow records complete flyology_bench samples,
environment, build logs, capability records, source and dependency attestations,
and artifact digests for macOS/Linux portable/native lanes. Parser comparisons
include yyjson, simdjson, RapidJSON, serde_json, simd-json, sonic-rs, Node, and
the available Ada implementation. Writer evidence includes the allocation-free
public streaming writer and separately labelled preconstructed-DOM serializers
from yyjson, RapidJSON, serde_json, and sonic-rs.

The writer lanes are not ranked as semantically equivalent. Flyology measures
semantic streaming calls into caller-owned staging without per-operation core
allocation. The independent `write_dom` lanes prepare reusable values outside
timing and include complete output allocation, serialization, a checksum over
every output byte, and cleanup inside timing. Every admitted population first
matches exact expected output.

## Limitations

- This is an experimental development release; later versions may revise its
  API.
- The trusted core has no accounting or budget surface for untrusted consumer
  integration.
- Binary64, decimal, and application-specific numeric conversions are not
  installed public units.
- Canonical JSON, a DOM, allocating conveniences, and consumer adapters are not
  supplied by this release.
- WPT remains pinned digest evidence rather than an executable imported corpus.
- The full quadratic every-split corpus replay is deliberately not executed;
  the exact refused work requirement and bounded substitute are recorded above.

## Review closure

Architecture, parser, writer, public API, corpus, benchmark, website, and
release changes use the repository's P0/P1/P2 review cycle. Publication is
permitted only after the final exact-origin re-review reports no P0 or P1 and
all P2 findings are fixed or explicitly authorized as limitations above.
