# Provisional corpus and license review

## Scope

Only fixture data, license text, manifests, provenance, exclusions, and
expectations are vendored. No upstream runner or other executable source is
included. The import checks the selected bytes before copying them, and the
offline verifier rejects missing, changed, extra JSON fixtures, symlinks, or
vendored WPT JavaScript.

The attested provenance object is the bytewise-sorted selected-file manifest,
not a provider-generated transport archive. Archive packaging and compression
may change without changing the pinned Git revision; every selected upstream
byte must instead match its retained per-file SHA-256 entry before import.

The historic JSON.org JSON_checker corpus is not vendored because its license
is incompatible with this repository's MIT/Apache-2.0 distribution policy.

## Provisional parser evidence

The private parser runner compiled with Ada 2022, all warnings as errors,
validity checks, overflow checks, assertions, and exception tracebacks. Across
all 394 JSON fixtures, monolithic, one-byte, and eight deterministic randomized
chunk schedules each reported zero unexpected terminal outcomes. The runner
checks terminal acceptance or error class, and requires every scheduled
malformed result to preserve the monolithic error code and byte offset. It does
not compare event or fragment sequences. The two duplicate-name fixtures now
require the exact `Duplicate_Name` status and every schedule must reproduce the
monolithic later-name opening-quote offset. Both pass with no retained gap; a
generic parse failure cannot satisfy the expectation. Malformed expectations do
not pass on `Depth_Exhausted` or `Offset_Exhausted`; fixture-derived storage for
100,000 levels lets the two long malformed documents reach their syntax result.

The corpus reader uses `Stream_Element_Array` values with lower bound one.
Randomized schedules use varying nonempty chunks and do not inject empty
chunks. The focused core suite covers arbitrary bounds and empty chunks;
`every-split` additionally requires an explicit empty nonfinal chunk at split
zero to return `Need_Input`.

The `every-split` action is implemented but was not executed in this
provisional run. Re-parsing the 100,000-byte and 250,001-byte truncated fixtures
at every split is quadratic. The runner now computes the complete campaign's
minimum planned-input plus `Next`-call work before parsing and requires an
explicit positive caller ceiling. Every actual `Next` call and every fixture's
planned input debit the same runtime ledger, which also bounds repeated
zero-consumption events and detects corpus growth after estimation. It refuses
an undersized ceiling without running any fixture, has no default, and never
silently skips a split after a mismatch. The full campaign remains an
intentionally authorized, sharded action rather than a routine local test.
A two-fixture every-split smoke run passed and exercises the split-zero empty
nonfinal call, but it does not satisfy or stand in for the full campaign.

The later `0.1.0-dev` release review computed the complete campaign at
82,539,090,222 work units. Under the user's explicit instruction not to run a
very large loop, the release gate is superseded rather than deferred: every
executable fixture retains monolithic, one-byte, and deterministic randomized
schedules, while bounded transition fixtures retain exhaustive splits and
partitions. The planner and refusal remain maintained so corpus growth cannot
silently turn a bounded action into an accidental quadratic run.

## Findings

- P0: none.
- P1: none after exact revision, selection, license, count, byte-total, and
  digest checks were made executable, expectations became immutable reviewed
  inputs rather than importer-generated labels, Linux digest tooling gained a
  fallback, and resource denial stopped counting as malformed rejection.
- P2: the later release decision above closes the full-corpus `every-split`
  gate with an explicitly authorized bounded substitute. WPT evidence remains
  intentionally non-executable. That gap does not remove current UTF-8 boundary
  coverage: JSONTestSuite supplies malformed UTF-8 data and the dedicated UTF-8
  tests exhaust all scalar encodings.
